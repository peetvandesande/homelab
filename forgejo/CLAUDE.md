# Forgejo

CT 303, **192.168.8.62**, `forgejo.home`, pool `Production`. Forgejo v15
(the LTS line) on HTTPS `:443` off the lab CA, git over SSH on `:22` through
the host's OpenSSH, PostgreSQL local to the container. Built 28 October 2026.

Known to everyone as **`git.peetvandesande.com`**: on the LAN that name is
split-horizon to this host, off it it is ruby, which proxies here over wg1
(`../CLAUDE.md`, "Public services").

## Working on this

`root/` mirrors the container filesystem and is the source of truth.

```
scripts/bootstrap.sh     create CT 303 on lenora and install (see its header)
scripts/deploy.sh        push root/, generate secrets once, restart
scripts/verify.sh        LAN, both families, SSH, ruby, monitoring
scripts/install-ruby.sh  on ruby: sudo ~/homelab/forgejo/scripts/install-ruby.sh
ruby/                    the public vhost it installs
```

Order for a rebuild: router reservation for the MAC in `bootstrap.sh`, then
`bootstrap.sh`, `ca/scripts/enrol.sh 192.168.8.62 forgejo
git.peetvandesande.com`, node-exporter, alloy, apt and fleet for `.62`, then
`deploy.sh`. A new MAC means a new ULA, so the AAAA in `dns/ansible` and the
split-horizon zone change with it.

Upgrading is `VERSION` in `bootstrap.sh` and a re-run, then `deploy.sh`. The
old binary stays beside the new one as `/usr/local/bin/forgejo-<version>`.

Accounts are made by an admin – registration is off. The first one:

```sh
ssh root@forgejo.home runuser -u git -- forgejo admin user create \
  --config /etc/forgejo/app.ini --admin --username <name> --email <addr> \
  --random-password --must-change-password
```

## Invariants

1. **`HTTP_ADDR` is empty, not `::` and not the default.** The default
   `0.0.0.0` serves IPv4 only. `::` works for the main listener, but the `:80`
   redirector builds its address as a string, gets `:::80`, and takes the
   whole process down with it. Empty gives `:443` and `:80`, Go's dual-stack
   wildcard (`bindv6only` is 0), and as a wildcard it needs no
   wait-for-address drop-in.

2. **`app.ini` is the whole config, and Forgejo cannot write it.** It is
   pushed `root:git 0640` with `INSTALL_LOCK`, so the web installer never
   runs and nothing set in the UI survives a deploy unless it is here. No
   secret is in it: each is a `*_URI` pointing at `/etc/forgejo/secrets/`,
   generated by `deploy.sh` the first time and never again. **`SECRET_KEY`
   encrypts 2FA secrets and stored credentials in the database**, so the
   secrets and the database are one backup or none.

3. **The database has no password.** The role is `git`, the OS user Forgejo
   runs as, and it connects over the Unix socket with peer authentication.

4. **SSH is OpenSSH asking Forgejo, not Forgejo's built-in server.**
   `sshd_config.d/forgejo.conf` runs `forgejo keys` per login as `git`, so a
   key added in the UI works on the next push and there is no
   `authorized_keys` to regenerate. It only works on the LAN and VPN: off
   them `git.peetvandesande.com:22` is ruby's own sshd. Two Debian 13 details
   in `deploy.sh`: sshd is socket-activated, so a **reload kills it** (the
   re-exec cannot bind `:22`, which the socket holds) – restart instead; and
   `sshd -t` needs `/run/sshd`, which only exists while sshd runs.

5. **The certificate carries `git.peetvandesande.com`.** Forgejo serves the
   lab certificate itself, and both LAN clients (split-horizon) and ruby
   (`proxy_ssl_name`) ask for that name. Drop the extra SAN from `FLEET` in
   `ca/scripts/enrol.sh` and both break at the next renewal. Forgejo has no
   certificate reload, so `post-renew.d/20-forgejo` restarts it.

6. **`/metrics` is open on the LAN and refused on ruby.** Like node-exporter,
   it has no token; the public vhost answers `/metrics` with 404 before
   proxying, and `verify.sh` checks that from outside.

7. **ruby is the only trusted proxy.** `REVERSE_PROXY_TRUSTED_PROXIES` lists
   ruby's tunnel and dummy ranges, so `X-Forwarded-For` is believed from
   ruby and from nothing on the LAN.

## Not done

- **No backup.** Repositories, LFS and attachments are under
  `/var/lib/forgejo`; the rest is in PostgreSQL; the secrets are in
  `/etc/forgejo/secrets`. All three go together.
- **No mail.** hermes delivers nothing outside the labs, so password resets
  and notifications are off (`[mailer] ENABLED = false`).
- **git over SSH from outside** would need a port on ruby forwarded over wg1.
  HTTPS covers it today.
